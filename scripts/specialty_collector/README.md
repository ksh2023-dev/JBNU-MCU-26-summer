# specialty_collector

전북대병원 교수 프로필 페이지에서 **전문진료분야**(데이터 계약 `specialties` 필드의 재료)를 수집한다.
임상 교수만 대상이며(기초 교수는 병원 프로필 페이지가 없어 대상 아님), 입력은 사진 수집기와 동일한
`data/input/professor_pages.json` (243명)를 사용한다.

## 실행

```bash
python scripts/specialty_collector/fetch_specialties.py
```

- 스크립트 상단 `LIMIT` 상수로 처리 인원을 제한할 수 있다 (기본 `None` = 전체 243명).
- 결과는 `data/output/specialties.json`에 저장된다.
- 요청 사이 `time.sleep(0.5)`로 서버 예절을 지키며, 병렬 요청은 하지 않는다.
- 요청 실패 시 1회 재시도 후에도 실패하면 `raw: None, specialties: []`로 기록하고 계속 진행한다(중단하지 않음).

## probe 결과 — 항목 위치·형식

프로필 페이지 3개(유희철·이창섭·김동찬) + 무작위 표본 8개, 총 11개 페이지의 실제 HTML을 확인해 결정했다.

- "전문진료분야"는 정적 HTML의 `<div class="infoBox ib1">` 블록에 들어 있다
  (자바스크립트 렌더링 아님 → 표준 라이브러리 `urllib` + `html.parser`로 파싱 가능).

```html
<div class="infoBox ib1">
    <div class="info-title icon">
        <strong class="tit"><i class="icon plusIcon" ...></i> 전문진료분야</strong>
    </div>
    <div class="info-con">
        <p class="conText"> 간담도, 췌장질환, 이식외과, 혈관외과, 간담췌질환 </p>
    </div>
</div>
```

- 확인한 페이지 전부에서 항목 구분자는 **쉼표(,)** 만 사용했다. 가운뎃점(·)은 실제로는 발견되지 않았지만
  지시서에 언급된 만큼 안전하게 쉼표·가운뎃점 둘 다 구분자로 처리하도록 구현했다.
- 항목 사이 공백이 페이지마다 제각각(없음/한 칸/두 칸)이라 분리 후 `strip()`으로 정리한다.
- "전문진료분야" 블록 자체가 없거나(예: 오신영), 있어도 내용이 공백뿐인 경우(예: 김지혜)가 있다
  → 이 경우 `raw: null, specialties: []`로 기록한다 (지어내지 않음 — 데이터 계약 0장 원칙 2).

## 파싱 방식 — HTMLParser (PR 리뷰 반영)

초안은 `전문진료분야.*?<p class="conText">(.*?)</p>` 정규식 하나로 값을 뽑았으나, PR 리뷰에서
지적된 문제들 때문에 **표준 라이브러리 `html.parser.HTMLParser` 기반**으로 재작성했다.
같은 페이지를 도는 `profile_image_collector/fetch_image_urls.py`와 구조·컨벤션을 맞췄다
(파서 클래스 → `fetch_html()` → 추출 함수 → `main()`).

`SpecialtyCollector` 파서가 하는 일:

1. **블록 범위 한정** — `<div>` 중첩 깊이를 직접 세어 `infoBox ib1` 블록 **안에 있을 때만**
   `<p class="conText">` 텍스트를 모은다. 블록의 제목(`<strong class="tit">`)이 실제로
   "전문진료분야"인지도 확인한다. 블록이 없으면 `(None, [])`.
   - 정규식 방식의 문제: 페이지의 탭메뉴·breadcrumb에도 "전문진료분야" 문자열이 있고
     뒤따르는 `infoBox ib2`(외래진료일정)에도 `conText`가 또 있다. 그래서 실제 블록이 없는
     페이지에서 **엉뚱한 섹션의 진료일정을 그 교수의 전문진료분야로 집어올 수** 있었다.
2. **HTML 엔티티 디코딩** — `html.unescape()`로 `&amp;` · `&nbsp;` · `&middot;`를 푼다.
   특히 가운뎃점을 `&middot;`로 쓴 페이지는 디코딩하지 않으면 가운뎃점 분리가 무효가 된다.
   `&nbsp;`가 남긴 비줄바꿈 공백(`\xa0`)은 일반 공백으로 바꾼 뒤 연속 공백을 한 칸으로 정리한다.
3. **`conText` 내부 태그** — 텍스트만 남기되 `<br>`은 버리지 않고 구분자 `", "`로 치환한다.
   그냥 버리면 `심장질환<br>부정맥`이 `심장질환부정맥` 한 덩어리가 된다.

## 괄호 처리

괄호 **안에도** 쉼표를 쓰는 사례가 다수 있다.

```
관절(어깨,무릎)통증
내분비질환(갑상선,부신,이상지질혈증,뇌하수체기능저하등)
척추 퇴행성 질환[경추 및 흉추 척수증, 요추 협착증, 추간판(디스크) 탈출증]
```

단순히 쉼표마다 자르면 `"관절(어깨"` / `"무릎)통증"`처럼 괄호가 깨진 항목이 생긴다.
`split_specialties()`는 **아직 닫히지 않은 괄호의 닫는 문자를 스택으로 관리**해서,
스택이 비어 있을 때(= 괄호 밖)의 구분자만 항목 경계로 인정한다.

여는 괄호는 **짝이 맞는** 닫는 괄호로만 닫힌다(`(`↔`)`, `[`↔`]`). 초안은 여는 문자 집합과
닫는 문자 집합만 세어서 `A(B]C`처럼 짝이 어긋난 경우도 닫힌 것으로 처리했는데(리뷰 지적),
지금은 짝이 맞지 않으면 괄호가 열린 상태로 남아 그 뒤를 나누지 않는다 —
애매할 때는 쪼개지 않는 쪽이 안전하다.

## 출력 형식

```json
{
  "collectedAt": "2026-08-16",
  "source": "https://www.jbuh.co.kr 교수 프로필 페이지",
  "specialties": {
    "유희철": {
      "raw": "간담도, 췌장질환, 이식외과, 혈관외과, 간담췌질환",
      "specialties": ["간담도", "췌장질환", "이식외과", "혈관외과", "간담췌질환"]
    }
  }
}
```

- `collectedAt` · `source` — 사진 수집기(`profile_images.json`)와 동일한 컨벤션.
- `raw` — `conText`를 평문화한 문자열(엔티티 디코딩·공백 정리). 값이 없으면 `null`.
  원문의 `<br>`은 raw에서 `", "`로 보인다 — 이것이 raw에 가해지는 유일한 치환이다.
- `specialties` — `raw`를 구분자로 나눈 배열. 검증은 `raw`와 대조해서 한다. 값이 없으면 `[]`.

## 최종 실행 결과 (243명, 2026-08-16 · HTMLParser 재작성 후)

- 수집(specialties가 1개 이상) 241명 / 빈 값(raw 없음) 2명 / 요청 실패 0명
- 빈 값 2명: **김지혜**(전문진료분야 항목은 있으나 내용이 공백) · **오신영**(항목 자체가 페이지에 없음)
  → 두 명 모두 정규식 버전과 동일하게 `raw: null, specialties: []`로 처리됨

### 구버전(정규식) 결과와의 레코드 단위 비교

값이 달라진 교수는 **2명**이며, 둘 다 **HTML 엔티티 디코딩**(리뷰 지적 2번) 때문이다.
이 페이지들은 괄호를 `&#40;` · `&#41;`로 인코딩해 두었다.

| 교수 | 구버전 | 신버전 |
| --- | --- | --- |
| 이민로 | `대장암&#40;복강경수술&#41;` (1항목, 깨짐) | `대장암(복강경수술)` |
| 이민희 | `만성 기도질환&#40;천식` / `COPD` / `기관지확장증&#41;` (3항목으로 잘못 분리) | `만성 기도질환(천식, COPD, 기관지확장증)` (1항목) |

이민희 사례가 실제 데이터 손상이었다. 괄호가 `&#40;`로 인코딩된 탓에 괄호 인식이 되지 않아
괄호 안의 쉼표에서까지 항목이 잘렸고, 그 결과 항목 수가 5개로 부풀려져 있었다(정상은 3개).

**범위 문제(리뷰 지적 1번)로 값이 바뀐 레코드는 0건이다.** 즉 이 243개 페이지에서는 버그가
실제로 발동하지 않았다 — 탭메뉴 문구가 "전문진료**센터**"라서 "전문진료분야"와 정확히 일치하지 않았고,
블록이 없는 오신영 페이지에는 "전문진료분야" 문자열 자체가 없어 정규식이 걸릴 곳이 없었다.
템플릿이 바뀌어 내비게이션·breadcrumb에 "전문진료분야"가 들어가는 순간 잘못된 값을 수집하게 되는
**잠재 버그**였으며, 블록 범위를 한정해 원인을 제거했다.
